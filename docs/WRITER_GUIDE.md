# Гайд сценариста

Как написать сцену, поставить её на экран и сделать так, чтобы она запускалась в игре. Полный справочник тегов — [SCENE_FORMAT.md](SCENE_FORMAT.md), данные тайтла — [TITLE_FORMAT.md](TITLE_FORMAT.md), требования к арту и звуку — [ASSETS.md](ASSETS.md). Рабочий пример — [`content/titles/demo`](../content/titles/demo).

## Порядок работы

1. **Узнать ключи.** В студии их подсказывает редактор сцен. В файлах: персонажи и их эмоции — в `characters.yaml`, предметы — в `items.yaml`, характеристики — в `title.yaml`, квесты и достижения — в своих файлах. Ключ фона, музыки или звука — это имя файла ассета без префикса и расширения: `bg_gym.png` → `gym`, `music_calm.wav` → `calm`, `sfx_door_slam.wav` → `door_slam` ([ASSETS.md](ASSETS.md#6-имена-файлов)).
2. **Написать сцену** в студии («Сцены» → ключ новой сцены → «+») или файлом `content/titles/<тайтл>/scenes/<ключ>.ink`: имя файла без `.ink` — ключ сцены, папку потом импортируют в студию. Для файлов удобен [Inky](https://github.com/inkle/inky/releases): он ловит ошибки ink, но наших тегов не знает.
3. **Подключить сцену событием** в `events.yaml`, иначе её никто не увидит.
4. **Проверить.** В студии ошибки сцены видны сразу в редакторе, ошибки тайтла — после сохранения и при сборке. Для папки — из `apps/api`:
   ```bash
   uv run python -m storymaker_api.game check ../../content/titles/<тайтл>
   ```
   Ошибки приходят с номером строки: `scenes/anna_meet.ink:12: ...`. Предупреждение «сцену не запускает ни одно событие» значит, что вы забыли шаг 3.
5. **Проверить достижимость** симулятором: в отчёте видно, какая доля игроков увидела сцену. 0% — сцена недостижима.
   ```bash
   uv run python -m storymaker_api.game simulate ../../content/titles/<тайтл> --strategy romance:anna
   ```

## Редактор сцен в студии

Слева — сцены тайтла, в центре — текст, справа — сцена в рамке телефона.

- **Подсказки.** После `#` — теги, после `# show:` — персонажи, затем их эмоции и позиция; после `# bg:` — фоны локаций и загруженные; после `# effect:` — эффекты и их ключи (предметы, характеристики, флаги, квесты, достижения); после `->` — узлы сцены; в `{…}` — функции `affection("…")`, `has("…")`; в начале строки — кто говорит. Ctrl+Пробел открывает подсказки вручную.
- **Ошибки** подчёркиваются в строке, текст — при наведении и списком под редактором (щелчок по строке переносит к ней). Проверяет тот же компилятор с теми же ключами тайтла, что и сборка: чисто в редакторе — чисто и при сборке. Предупреждения ink (например, «loose end» — ветка кончилась без `-> END`) приходят на английском.
- **Сохранение** — Ctrl+S или кнопка. Сохранить можно и с ошибками, но сборка такую сцену не пропустит. Если сцену тем временем сохранил кто-то ещё, студия не затрёт его правку и предложит выбрать: сохранить поверх или загрузить его версию.
- **Превью** играет последнюю версию без ошибок. Запустить можно с начала, с любого узла или с узла под курсором. В «Состоянии на старте» задаются симпатия, характеристики, предметы, флаги и уровень аккаунта — то, что сцена видит через `affection()`, `has()`, `flag()`, `stat()` и `global_level()`. В конце видно, какие эффекты сцена отдаст игре. Чего нет среди загруженных ассетов, рисуется заглушкой.
- **Навигация:** F12 на `-> узел` — перейти к узлу, Ctrl+Shift+O — список узлов, Ctrl+G — к строке, Ctrl+F — поиск.

Игроки увидят изменения после сборки и публикации.

## Когда запускается сцена

Сцена сама не знает, когда её показывать. Это решает событие в `events.yaml`:

```yaml
anna_meet:                        # ключ события
  trigger: { enter: gym }         # что сделал игрок
  when: { time.slot: evening }    # при каком условии
  scene: anna_meet                # какую сцену показать
  effects: { set: { flag.met_anna: true } }
```

| Триггер | Когда срабатывает |
|---|---|
| `{ enter: <локация> }` | Игрок вошёл в локацию |
| `{ activity: <занятие> }` | Игрок выполнил занятие из `activities.yaml` |
| `day_start` | Наступил новый игровой день |

- `when` — условие на состояние игры: симпатия, флаги, предметы, время, день недели, квесты. Синтаксис — в разделе «Условия» [TITLE_FORMAT.md](TITLE_FORMAT.md#условия).
- `once` — по умолчанию `true`: событие срабатывает один раз за игру. Для повторяющихся сцен ставьте `once: false`.
- `priority` — если на одно действие подходит несколько событий одного вида, срабатывает одно, с наибольшим приоритетом.
- `effects` события применяются вместе с эффектами сцены. Флаг «сцена уже была» удобно ставить здесь, а не в сцене.

Цепочка сцен строится флагами: первая сцена ставит `flag.met_anna`, событие второй сцены проверяет его в `when`.

## Текст и выборы

```ink
Вечерний зал почти опустел.        // повествование
anna: Опять ты?                    // говорит персонаж с ключом anna
me: Может, и не совпадение.        // протагонист, имя подставит игра

* [Остаться]
    anna: Тогда помоги со штангой.
* [Уйти] # effect: affection anna -1
    anna: Ну и ладно.
- anna: До завтра.
-> END
```

- Сцена идёт с первой строки и должна закончиться `-> END`.
- Реплика определяется по началу строки `ключ: `. Повествование не должно начинаться с латинского слова в нижнем регистре и двоеточия, иначе игра примет его за реплику персонажа.
- Условие для варианта пишется прямо в выборе: `* { affection("anna") >= 10 } [Обнять]`. Доступные функции — в [SCENE_FORMAT.md](SCENE_FORMAT.md#чтение-состояния-игры).
- Платный вариант: `* [Позвать на кофе #premium: 15]`. В каждом выборе должен остаться хотя бы один бесплатный вариант.

## Постановка: фон и спрайты

Каждая сцена открывается на пустом экране и в тишине. Поэтому в начале сцены задайте фон, а при необходимости и музыку.

```ink
# bg: gym
# show: anna neutral left
anna: Привет.
# show: anna smirk
anna: Опять ты?
# show: max happy right
max: Всем привет!
# hide: anna
```

| Нужно | Тег |
|---|---|
| Сменить фон | `# bg: <фон>` |
| Вывести персонажа | `# show: <персонаж> <эмоция> [left\|center\|right]` |
| Сменить эмоцию | `# show: <персонаж> <эмоция>` — персонаж останется на своём месте |
| Переставить персонажа | `# show: <персонаж> <эмоция> <новая позиция>` |
| Убрать персонажа | `# hide: <персонаж>` |

- Тег на отдельной строке срабатывает **перед** следующей репликой. Несколько тегов подряд выполняются по порядку.
- Без позиции новый персонаж встаёт в центр. На экране три позиции: `left`, `center`, `right`.
- Эмоция должна быть в списке `emotions` персонажа в `characters.yaml`, иначе `check` выдаст ошибку. Нужна новая эмоция — добавьте её в список и закажите арт.
- Фон локации, в которой стоит игрок, задаётся в `locations.yaml` (`background`). В сцене фон всё равно указывается явно, обычно тем же ключом.

## Звук

| Нужно | Тег |
|---|---|
| Включить фоновую музыку | `# music: <трек>` — играет по кругу |
| Сменить трек | `# music: <другой трек>` |
| Выключить музыку | `# music: stop` |
| Звуковой эффект | `# sfx: <звук>` — проигрывается один раз |

- Повторный `# music:` с тем же треком не перезапускает его, музыка продолжает играть.
- В конце сцены музыка останавливается сама.
- Браузер включает звук только после первого касания экрана. Не ставьте на первый экран сцены звук, без которого она непонятна.

## Катсцены и драматические моменты

Отдельного формата катсцен (видео, анимаций) нет. Постановочный момент собирается из обычных тегов: полноэкранный фон или CG как `bg`, паузы, звук и эффекты экрана.

| Тег | Что делает |
|---|---|
| `# wait: <секунды>` | Пауза перед следующей репликой, до 10 секунд |
| `# fx: shake` | Встряска экрана |
| `# fx: flash` | Белая вспышка |

```ink
# music: stop
# hide: anna
# bg: street_night
# sfx: thunder
# fx: flash
# wait: 1.5
Гром ударил совсем рядом. Свет в окнах погас.
# bg: street_dark
# sfx: footsteps
# wait: 2
Кто-то шёл за мной.
# fx: shake
# show: max neutral center
max: Не бойся. Это я.
-> END
```

Советы:
- Сюжетная иллюстрация (CG) — это просто фон со своим ключом, например `first_kiss` (файл `bg_first_kiss.png`). Спрайты перед ней уберите через `hide`.
- Вариант фона по времени суток — тоже отдельный ключ: `# bg: cafe_evening`. Сам по времени суток фон не меняется.
- Паузы не должны быть длинными: игрок не может их пропустить. Одна-две секунды обычно достаточно.
- Чтобы катсцена шла в нужный момент, запускайте её отдельным событием: например, `day_start` с `when: { time.day: 7 }` или вход в локацию с флагом.

## Эффекты сцены

Эффекты (`# effect: ...`) меняют состояние игры: симпатию, характеристики, предметы, флаги, квесты, опыт, достижения. Полный список — в [SCENE_FORMAT.md](SCENE_FORMAT.md#эффекты). Главное:

- У симпатии и характеристик знак обязателен: `+3`, `-1`.
- Значения пишутся прямо в теге, переменные и выражения не работают.
- Эффекты применяются сервером, когда сцена закончилась. Функции `has()`, `affection()` и другие уже видят их внутри сцены.
- Валюту и платные предметы сцена не выдаёт.

## Ограничения сейчас

- **Ключи фонов, музыки и звуков `check` пока не проверяет.** Опечатка в `# bg:` или `# music:` не даст ошибку, а в игре просто не будет картинки или звука. Студия показывает их на странице тайтла в разделе «Ассеты» → «Не хватает» и в предупреждениях сборки: опечатка в ключе выглядит как недостающий файл. Список ассетов демо-тайтла — в [ASSETS.md](ASSETS.md#7-список-ассетов-демо-тайтла).
- Эмоция переключается мгновенно, без перехода. Новую эмоцию заказывайте у художника заранее; общий набор ключей эмоций — в [ASSETS.md](ASSETS.md#53-эмоции).
- В ключе нового персонажа не используйте `_`: в имени файла спрайта он отделяет персонажа от эмоции.
- Видео, анимаций спрайтов и плавных переходов между фонами нет. Если сюжету нужно что-то из этого, заведите задачу на движок.
- Поставить выбор внутрь блока `{ условие: ... }` нельзя: ink выдаст ошибку. Условие пишется в самом выборе.

## Чек-лист перед сдачей сцены

- [ ] Сцена заканчивается `-> END`, в начале задан фон.
- [ ] Все персонажи и эмоции есть в `characters.yaml`.
- [ ] Ключи фонов, музыки и звуков сверены со списком ассетов.
- [ ] В каждом выборе есть бесплатный вариант.
- [ ] Сцену запускает событие в `events.yaml`, условия `when` проверены.
- [ ] `check` проходит без ошибок, симулятор показывает, что сцену видит больше 0% игроков.
